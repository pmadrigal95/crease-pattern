Parallel code that actually scales

Most parallel code gets slower as you add threads. A solver you can run in your own browser shows why, and the design that fixes it.

Split one problem across 4 threads and it finishes about 3.1× faster, until the threads start waiting on each other.

That curve is a model. Your computer can tell the truth: this splits a prime-counting job across real Web Workers.

About

As products grow, frontends tend to become the reason teams ship slower. My job is to make sure they don't: component architecture, design systems, automated tests and the pipelines that ship them. I've done it since 2017, and as Lead Frontend Architect since 2024.

I hold a high bar on the parts nobody sees until they break: focus states, contrast, frame budgets, and the decisions written down next to the code. This page is the proof; press Shift+I.

Away from the keyboard I'm usually on a trail, a volcano or a dirt road somewhere in Costa Rica.
